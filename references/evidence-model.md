# 事实证据模型

## 目的

产品交付文档同时包含目标、当前实现和验证结论。三者必须分开，否则文档会把计划写成事实，或把一次测试结果写成长期能力。

## 事实类型

| 类型 | 含义 | 常见来源 |
|---|---|---|
| 产品目标 | 已确认应当实现的行为 | 获批需求、决策记录、验收标准 |
| 当前实现 | 当前代码和配置实际具备的行为 | 页面、路由、服务、任务、数据库、配置 |
| 验证证据 | 某个版本或环境中实际验证过的结果 | 自动化测试、人工验收、运行日志、截图 |
| 外部事实 | 第三方系统或远程环境提供的事实 | 官方契约、远端回读、受控探针 |

同一句话如果同时涉及多种类型，应拆开描述。例如：“目标要求支持取消；当前只实现提交申请；生产环境尚未验证最终取消结果。”

## 证据优先级

没有项目自定义规则时，按以下顺序处理冲突：

1. 用户本次明确确认的产品决策；
2. 当前运行时或数据库的只读证据；
3. 当前分支代码、schema、路由和配置；
4. 当前版本测试及其真实输出；
5. 当前契约、计划和变更记录；
6. 历史文档、截图、聊天记录和示例数据。

高优先级不意味着可以静默覆盖低优先级。发现冲突时记录冲突、影响和需要修正的事实源。

## 状态标签

| 标签 | 使用条件 |
|---|---|
| `VERIFIED` | 当前版本和声明范围已有直接证据 |
| `IMPLEMENTED` | 当前代码存在，但尚缺少完整验证证据 |
| `PARTIAL` | 只覆盖部分场景、角色、入口或环境 |
| `PLANNED` | 已确认目标，但尚未实现 |
| `UNKNOWN` | 现有证据无法判断 |
| `BLOCKED` | 因外部依赖、权限或缺失决策无法继续 |
| `OUT_OF_SCOPE` | 已明确不属于当前范围 |

不要用时间词替代状态。例如“近期上线”不能证明 `IMPLEMENTED`，旧测试通过也不能自动证明当前版本 `VERIFIED`。

## 证据记录

重要事实至少记录：

- 事实或结论；
- 状态标签；
- 适用版本、分支或环境；
- 证据位置；
- 证据日期；
- 限制或未覆盖范围。

示例和模拟数据只能证明格式或交互设计，不能证明真实业务结果。
